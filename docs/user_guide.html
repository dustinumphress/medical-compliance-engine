Medical Compliance Engine

User Guide

Audit operative reports against CPT codes, catch denials before they happen, and generate payer-ready appeal letters — with deterministic CMS rules doing the enforcement and Claude doing the judgment.

01How it works

The engine layers four checks over every audit, in a strict trust hierarchy — higher layers override lower ones:

  1. Rules-engine exclusions (HARD FAIL) — known denial triggers, e.g. cosmetic-intent language on CPT 15730. Negation-aware ("no cosmetic intent" won't fire) and carve-outs for legitimate phrases like "aesthetic subunit."
  2. NCCI / MUE database checks — 2.3M CMS bundling edits (filtered to currently-active edits only) and 15K unit limits with MAI severity, queried deterministically.
  3. Rules-engine requirements — missing "magic words" (deep fascia, vascular pedicle, named muscle) force a MEDIUM alert even if the AI passes the code.
  4. Claude verification — does the narrative actually support each code? Quotes its evidence, independently counts supportable units, and validates diagnosis specificity.

PHI never leaves your machine un-redacted: Microsoft Presidio runs locally and you review the redacted text before anything is sent to the API.

02First-time setup

Requirements

  • Python 3.12 — not 3.13/3.14; the PHI engine (spaCy/Presidio) breaks on newer versions
  • An Anthropic API key, or AWS credentials with Bedrock access

Install

py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
# spaCy's downloader can fail with new pip — install the model wheel directly:
.venv\Scripts\python.exe -m pip install https://github.com/explosion/spacy-models/releases/download/en_core_web_lg-3.8.0/en_core_web_lg-3.8.0-py3-none-any.whl

Configure .env

# Option A — Anthropic direct (required for Fable 5)
LLM_PROVIDER=anthropic
ANTHROPIC_API_KEY=sk-ant-...

# Option B — AWS Bedrock
LLM_PROVIDER=bedrock
AWS_REGION=us-east-1
BEDROCK_MODEL_ID=anthropic.claude-sonnet-5

# Real use = demo mode off
DEMO_MODE=false
Fresh clones only Two files are deliberately not in the public repo because they contain AMA-copyrighted CPT descriptor text: execution/clinical_policies.py and execution/cpt_data.py. On this machine they already exist. On a fresh clone, copy the .example.py stubs and fill them in — the app still runs without them, falling back to the CMS short descriptions in the database.

Build the rules database (fresh clones)

coding_rules.db is a local artifact. Download the CMS files and run execution/ingest_coding_rules.py — full steps in directives/refresh_coding_data.md (§ 09 below).

03Running the app

.venv\Scripts\python.exe app.py

Then open http://localhost:5000. Alternatively, run_app.ps1 runs the Dockerized version (starts Docker Desktop if needed).

Verify everything's healthy any time with the test suite:

.venv\Scripts\python.exe -m pytest tests\ -q      # expect: 31 passed

04Auditing a report

  1. Paste the operative report. Scrub obvious PHI first — the redaction engine is a safety net, not a substitute.
  2. Enter CPT codes with billed units. The Mod field is optional — leave it blank for an unmodified claim; enter comma-separated modifiers (59, XS) only when they're actually on the claim.
  3. Enter ICD-10 diagnosis codes.
  4. Pick a model. The dropdown loads the live model list with pricing (see § 08). Sonnet 5 is the everyday default; Fable 5 for the hardest calls.
  5. Review & Audit. The redaction modal shows the original with highlights and the sanitized version — edit the sanitized text if Presidio missed something, then approve.
  6. Results render per code; the chat box below lets you ask the auditor follow-ups ("why did 15734 fail?", "what would make this pass?").

05Reading the results

AlertMeaningWhat to do
HIGH – NCCI BUNDLING Active CMS edit bundles this code into another billed code. Indicator 1: add 59/XS if a distinct service is documented. Indicator 0: cannot be billed together, period.
HIGH – MUE EXCEEDED Billed units exceed the CMS limit. Rationale explains the MAI class. MAI 2 is an absolute daily max. MAI 3 is appealable with documentation.
HIGH – SYSTEM GUARDRAIL A hard exclusion fired (e.g. cosmetic-intent language on 15730). Fix the narrative or the code — this pattern is a known auto-denial.
MEDIUM – NCCI (MODIFIER APPLIED) Bundling edit exists but your 59/X-modifier can override it. Confirm the note documents the distinct service/site the modifier claims.
MEDIUM – MISSING KEYWORDS Required documentation concept absent (deep fascia, named muscle…). Request an addendum before submitting, or expect a documentation denial.
UNIT DISCREPANCY The AI's independent unit count differs from what you billed. Re-measure against the note; adjust units or gather support.
NONE No deterministic or AI risk found. Still verify — this is audit support, not a guarantee.

Each row also shows documentation status (PASS / PARTIAL / FAIL), the evidence quote pulled from your note, and calculated vs. billed units. Below the table: diagnosis-specificity analysis, documentation-improvement advice, and the audit's token usage with estimated dollar cost.

06Modifiers

Modifiers are always optional. A blank field is a normal claim and is never penalized. When you do enter one:

  • Distinct-service modifiers — 59, XE, XS, XP, XU — on the component code of an indicator-1 NCCI pair downgrade the alert from HIGH to MEDIUM, with a reminder that the note must support the distinct service.
  • Indicator-0 edits cannot be overridden by any modifier — the alert stays HIGH and says so explicitly.
  • Other modifiers (LT/RT, 50, etc.) are passed to the AI as claim context but don't change deterministic alerts.

07Appeal letters

After any audit, the Appeal Letter panel appears under the results:

  1. Choose one CPT code or "All billed codes."
  2. Optionally paste the payer's denial reason — a remark code (CO-50, CO-97) or the letter's own language. Without it, the engine anticipates the most likely denial rationale from the audit findings.
  3. Generate (30–60s). The letter quotes your operative documentation, cites the applicable policy excerpts, rebuts the denial rationale, and closes with a reprocess request.
PHI Letters use placeholders — [PATIENT NAME], [CLAIM NUMBER], [DATE OF SERVICE] — because the engine only ever sees redacted text. Fill those in outside the tool; never paste identified patient data back in.

08Models & costs

The model dropdown queries the provider's live model list at page load — new models appear automatically, nothing is hardcoded. Prices come from a lookup table by model family (there is no pricing API), so a brand-new family shows "pricing unknown" until the table is updated in execution/medical_audit.py → MODEL_PRICING.

09Keeping it updated

Quarterly — CMS rules data (most important)

CMS updates NCCI edits and MUE limits every quarter (Jan 1 / Apr 1 / Jul 1 / Oct 1). Stale data means missed edits on new code pairs. Full procedure lives in directives/refresh_coding_data.md; the short version:

# 1. Download to the project root:
#    - NCCI PTP practitioner files from CMS.gov  (ccipra-*.txt)
#    - MUE practitioner CSV from CMS.gov         (MCR_MUE_*.csv)
# 2. Rebuild the database:
.venv\Scripts\python.exe execution\ingest_coding_rules.py
# 3. Verify:
.venv\Scripts\python.exe -m pytest tests\test_coding_logic.py -q

Annually — CPT short descriptions

Update the RVU filename in ingest_coding_rules.py to the new year's file (e.g. PPRRVU2027_Jan_nonQPP.txt) and re-run the ingest.

As needed

  • Model prices change → edit MODEL_PRICING in execution/medical_audit.py (model list updates itself)
  • New CPT codes to enforce → add an entry to CPT_RULES in execution/rules_engine.py (pure data — exclusions + required patterns) and a definition in cpt_data.py; optionally a policy block in clinical_policies.py
  • Dependencies → pip install -U -r requirements.txt, then run the full test suite before trusting results

10Command-line use

.venv\Scripts\python.exe execution\medical_audit.py ^
    --cpt 15734 15738 --dx L89.154 ^
    --file inputs\input_record.txt

Prints a color-coded table with per-code status, risk, evidence, and cost metrics, and writes the full JSON to .tmp/audit_result_latest.json. Put the op report in a text file under inputs/ (that folder is git-ignored, so notes never leak into the repo).

11Deploying to AWS (optional)

The serverless demo path: build the Docker image, push to ECR, then deploy the CloudFormation stack with deploy.ps1 (it prompts for the image URI). Notes:

  • The function URL now defaults to AWS_IAM auth. Deploying it public again requires explicitly passing FunctionUrlAuthType=NONE — remember a public URL lets anyone spend your Bedrock tokens.
  • The Lambda role is scoped to bedrock:InvokeModel on Anthropic models only.
  • .dockerignore keeps .env, credentials, tests, and docs out of the image.
  • The deployed demo runs with DEMO_MODE=True (canned scenarios, no free-text input, no appeal generation) to prevent abuse.

12Troubleshooting

SymptomCause & fix
Import error mentioning pydantic / "REGEX" Venv is on Python 3.13/3.14. Rebuild it with py -3.12 -m venv .venv and reinstall.
spacy download says "requires pip or uv" New-pip incompatibility — install the model wheel directly (command in § 02).
Model dropdown shows "Provider default model" The /models query failed — invalid/expired API key (direct) or expired AWS session (Bedrock: run aws login again). The app still works with the default model.
Chat or audit returns an API error Check .env credentials and LLM_PROVIDER. Bedrock also requires model access enabled for the region in the AWS console.
Fable 5 request refused Fable runs safety classifiers; clinical text occasionally trips false positives. Re-run on Opus 4.8 or Sonnet 5.
An NCCI alert looks wrong Check data vintage — SELECT MAX(effective_date) FROM ncci_edits; — and run the quarterly refresh (§ 09). Note the date filter assumes today as date of service.
